# 巡线者 v4：完整人物逐帧补绘样板

日期：2026-10-09。按用户对 v3 方法的纠正实施。

## 方法与本轮产物

用户要求的是画出更细致的中间步态，并按顺序播放。v3 的关节求解和部件变形没有满足这个要求，保留为历史试验，不继续作为本轮制作方法。

v4 保留原 v2 八张关键帧。在每对相邻关键帧之间补绘两张完整人物，共 **8 张原关键帧 + 16 张新画面 = 24 帧**。原八帧在原生图集中的像素完全不变。每张新画面包含完整的上身、裤装、膝部、靴子、衣摆和遮挡关系，来自内置 ImageGen 绘图，不来自骨骼变形、腿部胶囊、透明叠化或重复图。

播放顺序为：关键1 → 补绘1/3 → 补绘2/3 → 关键2 → …… → 关键8 → 补绘8→1的1/3 → 补绘8→1的2/3 → 关键1。最后一张没有复制第一张。

`source/`保存两组补绘原图、三张定向修订的原图和完整提示词。修订的三张对应3→4的两张过渡及6→7的第一张过渡。输入参考来自原v2的相邻关键帧；配对参考板按原图384×512单元重新排列，可由原图无损复建。

素材导入仅做透明边缘筛选、原图分辨率统一和整张人物的头部位置对齐。对齐不是姿态生成，不伸缩身体部件。生成图中越过虚拟单元边界的脚尖，按透明连接区域归属人物，保留完整图形，不直接切断脚尖。原生运行候选沿用原32色和128×128画布；另保留较大原画图集供细节评审。

## 时序与观看

- 原每个50ms关键帧间隔拆为17+16+17ms，总周期400ms。原关键帧仍在原时间点出现。
- 预览和动画WebP采用400ms周期；正常速度约60张姿态/秒。
- GIF只能使用百分之一秒计时，为兼容常用查看器每帧20ms，总周期480ms。观察原节奏请用网页、WebP或视频。
- 预览可切换原画／游戏像素尺寸、原八帧／新版24帧／历史v3，支持逐帧、慢放、上一帧叠图、单独接缝播放。
- 循环视频用隔离浏览器从本地图集录制为WebM，实际解码及全部24张画面出现均已检查。视频供观看；精确时序以原生源、图集元数据和WebP为准。

主要文件：`.aseprite`逐帧源、原生PNG图集、原画PNG图集、WebP、兼容GIF、24帧总览与`metadata.json`。制作方法、每一帧的原图来源、对齐量和校验值均保留。

## 重建

```powershell
python scripts/animation/build-ranger-drawn-inbetweens.py
python scripts/animation/verify-native-review-assets.py
python scripts/animation/verify-ranger-drawn-inbetweens.py
python scripts/qa/build-pixel-production-review.py
node scripts/qa/verify-ranger-drawn-review.mjs

```

最后一次生成页面用于加入已通过播放检查的视频链接。浏览器录制嵌入本地图片字节，使画布保持可录制状态，不需要安装系统编码器。

## 验收边界

文件检查能证明原帧保留、补绘数量、来源、时序和播放顺序。循环前后头部位置相差不超过1个原生像素，接缝像素变化处于内部变化范围；这些不是人体自然度或纹理稳定性的审美评分。

新画面的衣褶、配饰位置和个别过渡仍需视觉修画。保留原八帧也保留了原关键姿势中尚未完全解决的步态问题；不会把补帧视为它们自动被修正。该样板由绘图模型补绘，不宣称专业动画师逐像素人工完成。

`visualApproved=false`、`runtimeIntegrated=false`、`complete=false`。人物与枪械仍在合并画面中；游戏表现、存档、数值和启动素材未改。原生图集约105KiB，解码像素1.5MiB；较大原画和视频只供离线评审。
