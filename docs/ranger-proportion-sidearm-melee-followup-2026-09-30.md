# 巡线者比例、腿部动作与持枪样板复核

日期：2026-09-30。范围：巡线者默认服饰的 Blender 动作源。活动游戏继续使用现有厚涂静态人物；本轮没有修改玩法数值、内容 ID、存档或 Windows 构建内容。此文承接[人物动画路线复审](./character-animation-pipeline-evaluation-2026-09-28.md)及[灰模动作复盘](./ranger-motion-reference-review-2026-09-29.md)。

## 本轮具体改动与依据

用户认为前一版**跑步节奏基本符合预期**，希望细化腿部关节运动与人物比例，之后加入持枪动作，并为将来的刀类近战预留结构。因此保留 24 帧双脚交替接地的时间安排，没有重复调速；参考既有《死亡细胞》3D 源转 2D 帧、Klei 可复用部件以及《哈迪斯》以原画校对模型轮廓的制作原则，重点对照项目已获认可的巡线者原画。没有复制其他游戏的角色或动作素材。

| 内容 | 已完成的源文件与发现 | 仍需视觉验收的部分 |
|---|---|---|
| 人物比例 | `ranger-proportions-v3.blend`：兜帽收窄、护目镜和面罩缩小；大腿与小腿由等粗圆柱改成有 5 道截面的宽松裤腿；靴子收窄；加入左右手 `weapon_mount` 挂点。把样板正交镜头俯角从暂用 42° 调到 35°，保留原先的 35° 水平偏角。 | 76px 的膝部比 42° 更可见，但仍是低细节体块，面罩、衣褶和鞋面都需按原画细化。35° 仍是样板参数。 |
| 腿部动作 | `ranger-run-ik-v3.blend`：保持上一版足底轨迹与节奏，增加身体侧向重心、轻微肩髋转动、每个姿势的膝盖极点位置、离地脚掌角度及衣摆微动。 | 用户尚未看本轮新版。主要检查膝部弧线、脚掌是否像踩实地面，以及色块下的步幅。 |
| 双手持枪 | `ranger-run-sidearm-v1.blend`：同一双手臂经 IK 握住枪柄和支撑点；枪械姿势模型只用于检查，实际游戏仍使用已有枪械插画与内容 ID。`weapon_aim` 与腿部动作独立，可旋转枪械和两手目标。 | 前向和侧向姿势可读；后向枪械会被身体遮住，需新的上身扭转及背/侧身素材。暂无正式射击、后退、横移组合验收。 |

## 可复核的结果

- `verify-ranger-run-ik.py` 对空手与持枪的 24 帧均通过：脚和手的控制误差为 0，左右手武器挂点始终贴住手腕，骨长稳定，靴底最低约 -0.0077 米，支撑脚每帧匀速后移约 0.08167 米，循环首尾一致。
- 四个瞄准角度的双手 IK 均可够到目标；这仅证明骨架可达。180° 的枪械在画面中被遮挡，**不能标为后向持枪动作完成**。
- `output/animation/ranger/run-ik-v3/review.html` 和 `output/animation/ranger/run-sidearm-v1/review.html` 提供灰模预览；`output/animation/ranger/color-study/unarmed/review.html`、`color-study/sidearm/review.html` 用原画色系的简单材质块帮助查看腿与外套边界。配色块没有手绘纹理，不进入运行素材。评审页可暂停、逐帧和切换 76px/152px，持枪彩色页已在本地 Edge 验证。
- 三份新 `.blend` 均不足 160 KB；项目 Windows 运行素材仍来自现有 `web/assets`。源模型、评审 PNG/GIF 和第三方参考没有加入安装包，故本轮不会增加玩家启动时的图片解码或运行内存。运行时性能待真正接入图集后再测。

## 后续制作顺序

1. **P0 · 玩家审看当前 76px 彩色短片。** 优先指出腿是否还僵硬、比例是否顺眼、双手枪位是否可信。此反馈决定需要修姿势、模型，还是开始精绘；不提前把样板合并进游戏。
2. **P0 · 完成持枪方向。** 增加侧身、背身躯干体积与上身转向，分别验证前进、后退和横移时向不同方向瞄准。右手枪柄、左手支撑、枪口三点须稳定；受击/停步不能让双臂悬空。此时仅做起始手枪一种姿势家族。
3. **P0 · 厚涂画风与图集。** 按当前原画修兜帽、护目镜、围巾、宽松裤腿、靴面与衣摆的色彩、笔触和遮挡；固定镜头批量导出透明 2D 帧，裁切并压成紧凑图集。上身/下身分层方案必须在实机尺寸验证腰部接缝。通过后才对巡线者默认服饰接入 Canvas，保留静态回退。
4. **P1 · Windows 实测。** 实际窗口下检查 720p–1440p、鼠标/手柄瞄准、长局帧率与图集解码内存；与当前静态版并排让玩家确认。随后再估其他服饰与敌人动画成本。

## 将来加入刀类近战武器时的边界

本轮只在骨架上准备左右手通用 `weapon_mount`。刀、匕首等动作应使用独立的 `melee_idle / windup / active / recover` 上身片段；右手可挂刀柄，左手依武器类型决定是否支撑。刀尖轨迹与攻击生效窗口应作为动作元数据导出，供视觉特效对齐，**伤害和命中仍由游戏规则计算**。

当前 `CombatSim.fireWeapon` 走的是发射弹丸路径，游戏也没有近战武器内容 ID。将来加入刀不是只增加一张图片：需要设计扇形或扫掠命中区域、每次挥击对同一敌人只命中一次、冷却与打断、升级/商店/存档内容注册、音效和手柄提示，并单独做命中边界测试。等巡线者持枪动作与新图集被玩家认可后，再开近战玩法切片；这次不顺带修改战斗规则。
