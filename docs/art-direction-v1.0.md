# 《荒原回响》v1.0 美术重构方案

## 1. 核心识别：荒原残卷

本轮不再把界面理解成一组平铺的深色矩形，而是把它设计成幸存者车队使用的“行动残卷”：旧钢板是承力骨架，压花皮革与油布承载信息，黄铜只标记可操作边缘，氧化红只标记主要行动与危险。感染者会越过框体边缘进入前景，形成可识别的破框轮廓。

设计参数：`DESIGN_VARIANCE 8 / MOTION 5 / VISUAL_DENSITY 6`。

三个必须持续出现的项目特征：

1. **回声刻度**：三段短横线、衰减波纹和编号构成页面识别符号；
2. **破框感染者**：怪物头、手或肩甲跨越边框，构成前后遮挡；
3. **车队实物材质**：钢、皮革、帆布和黄铜有明确厚度、亮边与投影，不使用玻璃拟态。

## 2. 参考机制与原创边界

| 参考对象 | 提炼机制 | 本项目的原创转译 |
|---|---|---|
| Darkest Dungeon | 强剪影、角色压入界面前景 | 感染者作为破框前景，但使用本项目变异组织、拼装护甲和回声刻度 |
| Hunt: Showdown | 旧纸、刮痕和实物化边框 | 改为废土车队的旧钢板、皮带扣和手写行动编号 |
| Slay the Spire / Hearthstone | 卡牌抬升、扇形入场、选中焦点 | 保留抬升和层级反馈，卡框改为车队改件牌，不复制商业游戏卡框 |
| Into the Breach | 战术信息短、数值优先、状态色稳定 | 行动参数只保留时限、威胁、目标三个一级信息 |
| Minecraft | 人物与装备槽围绕、背包规则网格 | 保留信息结构，人物、槽位、纹理和图标均使用本项目原创表现 |

商业游戏只用于分析抽象设计原则；不得复制角色、图标、卡框、标题、商标、截图或可识别构图。

## 3. 视觉层级

每个主要页面最多五层：

1. **世界层**：低对比荒原场景；
2. **后衬层**：主面板向右下偏移的厚钢背板；
3. **信息层**：帆布、皮革或深铁内容区；
4. **边缘层**：切角、压边、铆钉、编号和回声刻度；
5. **前景层**：角色、感染者肢体、枪口或吊牌越过边框。

不再允许三层以上“卡片套卡片”。同一页面只有一个主容器；次级区域通过材料差、分隔线和留白区分。

## 4. 配色与材质

| 令牌 | 色值 | 用途 |
|---|---:|---|
| `void` | `#100f0c` | 最深背景，不使用纯黑 |
| `coal` | `#1b1914` | 主面板暗部 |
| `iron` | `#34332d` | 结构钢板 |
| `iron-highlight` | `#858071` | 可交互亮边 |
| `canvas` | `#514936` | 信息承载区 |
| `paper` | `#ead9ad` | 主文字与纸面 |
| `rust` | `#b55238` | 主动作、危险 |
| `brass` | `#d2a64f` | 焦点、稀有度、关键数值 |
| `signal` | `#76a39a` | 感染/无线电等少量状态 |
| `moss` | `#879468` | 生存、已拥有 |

材质必须依靠实体明暗关系表现：左上 1px 亮边、右下 3–8px 深边、局部磨损和投影。禁止霓虹外发光、大面积透明面板和彩虹渐变。

## 5. 字体与可读性

- `display`：Fusion Pixel 12，仅用于游戏标题、页面标题、卡牌名称和短按钮；
- `ui`：Microsoft YaHei UI / Microsoft YaHei，用于说明、数值标签、长句和设置项；
- `mono`：Cascadia Mono，用于编号、键位和诊断数据；
- 正文不得再强制使用像素字体；像素字体的特征由标题承担；
- 720p 下正文目标不小于 12px，辅助说明不小于 11px，按钮文字不小于 14px；
- 主文字与底色对比目标不低于 4.5:1，大字号和装饰文字不低于 3:1；
- 超长文本优先换行或改写，不得默认缩到 8px；`fitText` 只用于短标签和数值行。

## 6. 页面重构

### 6.1 作战部署

- 左侧运输车与幸存者成为主视觉，允许车轮、枪管和感染者前景跨越内框；
- 右侧章节占据最大面积，模式与地图变成两张倾斜少量的行动票据；
- 时限、威胁、目标使用三栏大数字，不再挤成一行小字；
- “确认出征”保持唯一氧化红主按钮。

### 6.2 行装与背包

- 左侧人物从“小图标”升级为纵向主角陈列，护甲槽围绕人物但减少重复边框；
- 右侧背包仍保持 5×4，以便稳定操作记忆；选中物品抬升 4px并显示底部实体铭牌；
- 属性值与标签拉开字号差，生命、护甲、移动、增伤成为四个可扫读仪表；
- 破框怪物只做边缘叙事，不遮挡可点击格子。

### 6.3 商店

- 商品从等权卡片改为“货架 + 吊牌”：图标更大、价格位置固定、操作按钮统一；
- 当前分类使用实体标签页，不再由左右箭头夹住一块普通矩形；
- 铜币、金币固定在顶栏，并用不同材质币章区分。

### 6.4 战地改造卡

- 四张卡保留扇形进入和悬停抬升；
- 卡头、插画窗、正文和等级槽有明确厚度；
- 选中卡向前抬升并压暗其余卡，避免只靠边框颜色；
- 正文改用易读字体，不因字数缩到不可读。

### 6.5 公共页面

设置、档案、暂停、结算共享同一个 `screenFrame` 和 `sectionPlate`，但根据语义使用不同印章和边缘角色，不再各自拼装近似框体。

## 7. 原创素材策略

本轮生成两件透明前景装饰：

1. `ui-mutant-overhang-v1.png`：大型拼装护甲变异体，从右上方压住钢板边缘；
2. `ui-crawler-overhang-v1.png`：披旧布的感染者，从左下方探入界面。

两件素材只作为 UI 前景层，不参与碰撞和游戏规则。人物换装继续使用 `pixel-actors.js` 的分部件程序化绘制，避免位图角色与装备系统失配。

在线候选仅保留在调研记录中：Kenney 官方说明其资产页资源为 CC0，OpenGameArt 的 `Pixel Art Wasteland` 页面标注 CC0。由于其像素密度与本项目主视觉不一致，本轮不直接引入。任何后续下载必须把原始包、许可证、作者、来源和修改记录登记到 `assets-ledger.csv`。

## 8. 组件边界

新增 `src/render/ui/art-primitives.js`，只负责表现：

- `screenFrame`：主界面厚背板和切角外框；
- `sectionPlate`：非嵌套的信息分区；
- `sectionTitle`：标题、编号、回声刻度；
- `statBlock`：大数字属性块；
- `drawOverhangArt`：加载失败时安全跳过的前景素材；
- `focusBrackets`：键鼠与手柄共用焦点。

页面组件只组合这些表现原语并注册 action；不写入存档、不修改战斗规则。图片加载失败时必须保持页面完整可用。

## 9. 验收标准

- 1280×720、1920×1080 下主页面使用有效画布，不出现中央小窗；
- 所有关键正文在 720p 下不小于 11px，按钮不小于 14px；
- 主页面各有唯一视觉焦点和唯一主动作；
- 怪物装饰形成清晰前后遮挡，但不覆盖点击区域和文字；
- 键盘、鼠标、手柄焦点状态均可辨；
- 图片加载失败时功能与布局仍然成立；
- 全部自动测试、bundle 构建、180 秒普通模拟与 600 秒无尽模拟继续通过。
