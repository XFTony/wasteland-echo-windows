# 地图美术与交互改造执行计划

日期：2026-10-30。项目为Windows像素废土连续生存游戏，玩法为移动走位、自动瞄准射击、拾取、经验升级、返回地图交易站购枪/改件/支援，怪物随时间增强。目标玩家画像、最低配置和最终局长仍未确定；本轮不添加房间闯关或强制波间购物。

## 审查与方向

| 问题 | 为什么需要改 | 本轮方法 | 验证 |
|---|---|---|---|
| 768翻转绘画地表与小型像素角色不统一 | 微小纹理抢敌弹/拾取的注意，放大后缺乏一致像素尺度 | 新四材质×四变化图集；TileMapLayer铺地，按64逻辑像素采样、压低纹理对比 | 三图实窗，远近/四分辨率检查 |
| 地图物体和角色固定不同z层 | 玩家像贴在建筑上；怪物无法与独立物件自然交错 | 同z的DepthRoot按脚底Y排序，角色/敌人/塔台/实体交互物各有独立视觉节点 | 角色建筑前后、怪物屋后与45项地图检查 |
| 屋顶遮挡容易隐藏威胁 | 走位射击无法读出近处敌人 | 高物上部局部淡化，底座不淡；同时照顾玩家与380范围内敌人 | 比较屋前/屋后/无重叠状态；不改碰撞 |
| 场景内嵌公共资源副本 | 编辑独立TileSet/Profile可能无法同步生效 | 改为实际外置Profile、共享TileSet/材质，保留原铺图字节；生成工具在任何写入前检查已有内容 | 资源对象身份与引用路径回归，不重复维护副本 |
| 平面方块道具缺少语义 | 爆桶、补给、交易看起来像同一类图标 | 16物件透明图集，配合独立文字/轮廓；金币圆形、经验菱形 | 一眼区分，并核对真实触发行为 |
| 交易柜台可用位置不明确 | 有入口美术却不知何处按键 | 柜台地坪、由实际radius/视线计算的标记、实际绑定键提示 | 圈内可进入、购物暂停、关闭恢复 |
| 栅栏网格画出物理边界 | 视觉像被封路，实际可以穿过线 | 网格裁回实体footprint，不扩张碰撞 | 原几何不变，截图检查无越界线 |
| 塔台预览绿环不代表连通性最终通过 | 预览只做局部验证，确认才做三档导航 | 局部通过改琥珀，显示实体26×26底座与“通路将复核” | 确认仍走原连通性验证 |
| 极薄墙可在塔台基座与枪口之间 | 枪口已越墙时只查枪口→目标会穿墙 | 补查炮身到枪口的静态墙段，忽略自身基座 | 新薄墙回归；普通塔台原版对照继续过 |

## 工具采用

本轮采用Godot原生TileMapLayer、外置TileSet、MapArtProfile资源与独立物件节点。已形成可绘制GroundTiles，关闭图块自身物理/导航；当前人物由字典模拟而非CharacterBody2D驱动，Area2D/body_entered不能直接代替现有交互。

Better Terrain是后续自动连接候选，未声称在4.7.2验证；Terrain Autotiler已归档；Gaea暂不增加程序生成范围。大量地图协作时可评估Tiled+YATI，README有4.7.2实测证据。详见[工具调研](../research/godot-map-tools-2026-10-30.md)。

## 素材与结构

- 同套废土材质，三图分职责：旧城地砖/旧铺、锈轨金属地坪/货运设施、赤砂土色/风化设施。地图结构、碰撞、出生权重、经验和武器数值继续保留。
- 地面使用重复小图块；建筑、车辆和交互道具独立。源图为imagegen生成的1254方图，原样保存；运行时TileSet与区域裁剪引用原图，Shader完成逻辑像素采样，不做巨大地图位图。
- profile记录图集、区域、材质、颜色、物件高度；地图.scene保留布局，GroundTiles可直接在Godot画/擦。生成脚本仅首次建层；遇已有GroundTiles拒绝覆盖手工铺图。
- 所有按钮文字、数值、交互半径、碰撞均由代码/数据提供，不烘焙进图像。破旧店门增加封闭木板，避免把不可进入的房屋暗示成室内入口。
- 敌人视觉节点复用，实体模型/对象池/三档导航继续独立，装饰不会自动变成碰撞。物理变化必须另行登记与测通路。

## 已执行顺序

1. **工具/项目审核**：确认原生编辑链和当前CanvasItem/z关系、区分视觉与真实判定。
2. **素材规范**：生成地表与透明道具图集，检查alpha及每物件边界，登记原图/提示词/SHA。
3. **可编辑资源**：生成共享TileSet/ShaderMaterial、三图MapArtProfile与GroundTiles，保留真实世界坐标。收尾修正内嵌副本，实际引用独立资源；三图2304/3136/4096个图块数据字节不变。
4. **对象深度与交互**：同z脚底排序、上部遮挡、交易范围、实体道具、拾取区分、塔台预览/薄墙修复。
5. **复验**：原生规则/布局回归、地图45项检查、三图和建筑前后/柜台/道具截图、独立包自检。
6. **文件与素材整理**：全一级目录分类、活动/源/历史/输出索引、重复组与引用报告；保留历史源，不盲删。
7. **提交备份**：独立功能分支，源码/素材/来源/测试入Git；包和完整截图留output，核对远端头和CI。

## 后续优先级

| 优先级 | 下一步 | 方法与成本判断 | 通过条件 |
|---|---|---|---|
| P0验收 | 本人试玩三图与交易/塔台/爆桶 | 每图完整一局，逐条记图标与碰撞歧义；低成本但不可被截图替代 | 不误判可走区域和交互距离 |
| P0验收 | 动态高密度长局 | 已完成104敌短时渲染样本；后续长局检查Y排序/屋顶淡化、密集掉落与内存 | 威胁不被遮没、视觉池不增长；短样本不代替长局 |
| P1 | 地表边角过渡 | 真正补齐内外角/路口素材后，再验证内置Terrains或Better Terrain | 边角无缺口，避免只装插件不备图块 |
| P1 | 更明确的三图专属地标 | 旧城电台广场、货运起重/信号、赤砂水塔/风化设施逐件迭代 | 一屏能辨认地图；不牺牲走位环路 |
| P1 | 装饰实体语义审查 | 逐件标注solid/ground-decal；确需实体的灯柱等另加数据底座并测三档导航 | 不出现视觉挡路而模型无阻挡 |
| P1 | 横竖车辆专用视角 | 当前采用区域/旋转适配；后续绘制专用方向而非反复拉伸 | 光源、落地点和车长一致 |
| P2 | 声音/足迹/环境叙事 | 地表自定义数据供脚步/尘土，轻量且可关；再添加小故事贴花 | 反馈清楚，动态效果不遮敌弹 |
| P2 | 外部编辑器/受控变化 | 地图数量增长后试Tiled/YATI；Gaea只生成不影响关键路线的小变化 | 单一权威源，重导入不覆盖唯一人工内容 |

不在本轮顺带调整武器伤害、升级收益或生存曲线；不把对照字段数量当作独立玩法测试数量，不以插件维护时间代替本项目实测。
