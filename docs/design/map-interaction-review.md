# 地图交互审查与本轮修复边界

本项目玩家/敌人由固定60Hz字典模拟驱动，表现是Node2D；并没有CharacterBody2D自动接入TileSet物理。因此本轮TileMapLayer明确关闭collision/navigation，真实判定继续来自MapObstacle导出的底座与三档共享流场。

已确认并修复：

1. 原障碍全在global z=-10、玩家10、敌人整批画在一个CanvasItem；只给父节点开y_sort不成立。现已同z的DepthRoot承载玩家、池化敌人、道具、塔台与实体交互物，按脚底排序。
2. 视觉高度可向上伸出底座，但不移动原碰撞；高物上部对玩家和近处敌人淡化，底座保持不透明。45项地图测试覆盖几何未变、共享深度平面、排序锚点、前后淡化与复用不增长。
3. 交易站显示真实radius与视线可达标记、实际绑定键。只是交易范围，不宣称怪物无法进入或站在旁边无敌；战斗仍在打开商店后才暂停。
4. 旧栅栏线段越过footprint造成假封路，已裁回实体范围；横竖货车显示过窄已按长轴适配。未来仍需专用方向资产统一光源。
5. 爆桶/补给使用独立形状与可见标记；金币为圆形，经验为菱形。爆桶提示半径来自effectRadius，不从美术图猜测。
6. 部署预览的局部通过不保证最终连通性：改琥珀和实体底座边框，确认仍做三档导航检查。
7. 额外鲁棒性修复：基座(1536,1446)、1像素墙(y1391)可使朝上枪口(y1388)越墙。新增炮身→枪口段检测，回归验证有墙不射、移墙可射；未声称现有正常地图普遍存在此问题。
8. 收尾发现公共资源文件虽已生成，场景仍内嵌副本；现已改为外置Profile及真正共享的TileSet/材质，保留全部铺图字节。加入9项资源身份检查，地图检查总计45项；生成脚本先检查已有内容，再允许写入，避免报拒绝时已经覆盖Profile。

已完成104敌的短时实窗样本与三图四分辨率截图，未发现资源退出错误；它不代替动态长局与低配验收。剩余事项：装饰型灯柱/树/杂物的solid/ground-decal语义逐件验收；长局中敌人遮挡、掉落、内存；真实低配、DPI与手柄体验。未来若改用PhysicsServer/Area2D，应独立迁移并重新建立单一碰撞权威源，不能与当前模型各维护一套不同形状。
