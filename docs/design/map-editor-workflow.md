# 地图编辑与后续制作流程

当前权威项目：`godot/project.godot`；编辑器：Godot 4.7.2。保留连续计时、开放走位和地图交易站，本轮没有安装第三方地图插件。

## 先选择要改的层

| 修改目的 | 编辑位置 | 会改变什么 | 验证要求 |
|---|---|---|---|
| 地砖、泥地、道路外观 | 三张`scenes/maps/*.tscn`中的`GroundTiles` | 只改美术，不改变能否通行 | 看接缝、道路标记、角色和敌弹对比 |
| 一张地图的调色、路边线、道具图集/高度 | 对应`content/map_art/*_art.tres` | 该图视觉；共享材质变化可能同时影响三图 | 三图同位置截图，屋前/屋后遮挡 |
| 共享图块或采样效果 | `content/map_art/pixel_wasteland_tiles.tres`及同目录材质、`shaders/` | 三图共用地表/物件采样 | 四分辨率、包内资源、显存/帧时 |
| 移动已有建筑、车辆、栅栏 | 场景`Obstacles`中的`MapObstacle`节点位置/footprint | 实际底座位置、碰撞和导航 | 三档通路、交易可达性、出生/部署合法性 |
| 增减实体、交易/爆桶/补给位置 | 地图定义Resource与对应场景，保持ID一致 | 玩法状态与碰撞，需作为单独改动 | 内容/战斗/导航/交互回归；不能只改一张图 |
| 更换物件画面 | `assets/world/pixel_map_v2/`和Profile区域表 | 仅画面，区域/透明边缘/落地点需匹配 | 源图/运行图SHA登记；不把文字烘进图像 |

具体Resource文件名以`content/map_art/`实际列表为准。共享资源是共用对象；只想改一张地图时，先判断应改Profile参数还是另存资源，避免无意改变三图。

## 在Godot中修改地表

1. 打开目标地图场景，选择`GroundTiles`，在底部TileMap面板选择共享图集进行画/擦。
2. 当前4行是4种材质，每行4个变化。道路/地砖/土面/金属地坪按图集实际内容选取，不能仅按色调猜通行性。
3. 当前格为64世界单位。Atlas区域312源像素，Layer缩放64/312；不要单独把TileSet改成64而保留旧缩放，否则所有地面错位。
4. 场景已有道路标线、轨道、地标文字的原生绘制；在这些位置铺图时保留其语义。当前边缘混合只是降低重复接缝，尚未制作完整内外角Terrain组合。
5. 保存场景并F6检查地图；实际角色/交互需要F5运行主场景。编辑器预览和运行节点不是同一套临时对象。
6. 不重跑`build_pixel_map_art.gd`覆盖编辑结果。它仅用于首次建层，发现已有`GroundTiles`会主动拒绝。

`GroundTiles.collision_enabled`及`navigation_enabled`保持关闭。当前模拟不读取TileSet碰撞，打开会形成一套不能驱动角色的额外物理，不能解决碰撞问题。

## 物体底座与遮挡

- 障碍节点位置和footprint输出真实轴对齐底座，视觉可向上伸出。建筑的碰撞不以整个屋顶PNG矩形计算。
- 运行时`MapPropVisual`、主角、敌人、塔台、爆桶和补给在同一Y排序平面，锚点为落地基线；不能随意加不同z_index破坏前后关系。
- 高物上部68%在遮住玩家或附近敌人时淡化；下部32%保持可见。Profile的高度不改变碰撞尺寸。
- 新增装饰时先声明是实体还是贴花。实体需要数据底座和通路验证；贴花避免像一堵实际挡路的墙。
- 交易站的圈是实际交互半径和视线提示，不是无敌区域。只有打开商店后才暂停战斗/计时。
- 横竖车辆当前使用共用视图旋转适配，后续优先绘制专用方向，避免光源随着旋转改变。

## 每轮最小闭环

1. 先明确只改视觉还是也改实体布局，再编辑；不要同时重做武器数值和成长曲线。
2. 生成原画放`art/world/<工作包>/sources/`，可编辑源/提示词/来源一并保留；活动图放`godot/assets/world/`。
3. 用Profile记录区域、TileSet、材质及落地点；更新工作包manifest、`docs/assets-ledger.csv`和`CREDITS.md`。
4. 先跑`node scripts/godot/verify-native.mjs`。改物理时，旧版对照发生的差异必须解释，并增加针对新通路/交互的检查，不能删掉断言掩盖变化。
5. 实窗检查三图、960×540/720p/1080p/1440p、屋前/屋后、交易、爆桶、补给、塔台部署和密集敌群。键鼠/手柄提示都应匹配当前输入。
6. 运行`node scripts/assets/audit-workspace.mjs`，检查缺失路径、声明SHA不匹配及来源复核项。
7. 提交源码/图集/UID/导入设置/来源/验证摘要。导出包和完整截图保存在`output/`，构建manifest记录干净源码提交和SHA；新功能通过后再讨论正式Release。

## 下一轮建议

先本人试玩确认碰撞语义，再按成本依次做地表内外角/路口、三图专属地标、车辆专用方向。工具调研见[Godot地图工具](../research/godot-map-tools-2026-10-30.md)，优先级与验收见[地图计划](map-art-and-interactions-plan.md)。只有地图量或自动连接成本已成为实际瓶颈时再引入插件。
