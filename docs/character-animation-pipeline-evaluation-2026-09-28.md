# 《荒原回响》人物动作制作路线复审

日期：2026-09-28。范围：Windows 版的战斗人物运动及后续服饰、装备复用。本文记录调研和下一次样板门槛，不视为已完成动画，也不修改玩法、碰撞、内容 ID、60 Hz 逻辑或存档。

## 结论

**保留现有 Canvas 2D 游戏、独立武器和静态厚涂原画；停止把已完成的单角度整身插画切成肢体，再靠正弦步态或实时 IK 拼出跑步。下一次只制作一名巡线者的“有体积的动画源 → 经画风处理的 2D 动作图集”样板，优先试用简化 3D 骨架加离线渲染。**

这一判断针对的是本项目的现有输入：巡线者原图是正面偏三分之四角度的完成插画，不含背面、侧面、被遮挡的肢体体积及接触地面的关键姿势。切成透明件不会补出这些信息。IK 只负责让手、脚够到目标，无法自动创造重心转移、落脚、蹬地、髋肩反向摆动和背身透视。v1 整腿旋转、v2 十一部件膝肘 IK 都经过玩家试玩，玩家均认为跑步不自然。这两次失败已作为回退证据，而不是继续调参数的理由。

游戏已用独立 Git revert 回到之前认可的静态角色渲染。v1 `ca0ad11` 和 v2 `9bc2b8d` 的源码、图片和便携试玩包仍可回看；当前分支的活动包不包含这两版动作图集。

## 路线比较

| 路线 | 能否达到画风与自然跑步 | 服饰/装备复用 | 主要成本与风险 | 判断 |
|---|---|---|---|---|
| 在 v2 运行时代码上继续调腿幅、膝角和图片 | 单角度纸片仍有透视、遮挡和重心问题 | 有槽位，但动作质量未过关 | 反复微调容易继续消耗时间 | **停止作为主路线** |
| 专业 2D 分层绘制＋人工关键帧＋网格形变 | 可以，尤其适合 Klei 式平面画风；本项目厚涂三分之四视角需要新增前、后、侧画稿 | Spine 式附件可复用 | 逐方向重画和人工修帧成本高；需要专业动画制作流程 | 备选路线；若 3D 样板不能保住画风，再做一名人物的 2D 对照 |
| **简化 3D 角色与骨架 → 手绘风材质 → 固定镜头离线导出 2D 帧** | 有真实体积、转身与关节；《死亡细胞》的流程说明可先验证关键姿势 | 衣服和护具可绑定同一骨架与部件槽 | 前期建模、贴图和美术对齐成本最高；需要建模工具和人工审美校正 | **首选一个巡线者样板** |
| 游戏运行时整体改成实时 3D | 可做，但不是达成动作目标的必要条件 | 可复用 | 重做渲染、场景、性能和发行链路 | 不建议为此次问题迁移 |

## 下一次仅做一名主角的决策样板

1. **先做动作标准，再做资产。** 选巡线者默认服饰，保持现有面罩、兜帽、围巾、外套和体型剪影。以游戏实际 76 世界单位、960×540 到 1440p 观看尺寸定义美术验收。旧静态身体仍是背包肖像和运行时回退。
2. **建立可编辑源。** 一个简化、有完整前后左右体积的角色模型；骨架至少含骨盆、脊柱、头、肩、肘、腕、髋、膝、踝和脚尖。枪柄、前握点、头盔、胸甲、腿挂和靴子用稳定插槽。用固定正交/弱透视摄像机匹配游戏地图的视角，不直接用原画图片贴在平面模型上。
3. **无纹理阶段先验四个关键跑步姿势。** 接触、下沉、经过、腾空；逐帧检查脚掌是否着地、骨盆重心如何移动、肩和髋是否反向转动。再验前进、后退、左右横移，以及边移动边反向瞄准。跑步姿势在灰模阶段没有说服力就暂停，不进入皮肤和图集制作。
4. **再匹配厚涂画风。** 按原画逐件处理面罩、布料、光源和边缘，在实际显示尺寸检查身份是否保留；头部和衣摆允许少量逐帧人工修画。透明背景、固定脚底和握枪锚点；不能把文字或碰撞信息画进人物。
5. **最后离线导出并接入。** 从同一可编辑源批量导出朝向与动作帧，压成小型 WebP 图集；上身瞄准与下身移动可分层输出，枪保持独立。运行时只切帧和做轻量混合，沿用 Canvas 2D、现有规则、存档与资源按需加载。源模型、纹理、帧、裁切和许可都须入台账。

### 样板必须通过的门槛

- **先看无枪动作短片，再看带枪动作。** 玩家在实际游戏尺寸下能一眼读出落脚、摆腿、重心与方向，且不会觉得像纸片或脚底滑行；与当前静态版并排比较。
- 正向跑、后退射击、左右横移射击及停步共至少五个状态。枪的右手握柄、左手支撑不漂移，变向和撞墙不乱跳。
- 只测一名主角、一套服饰和一把起始枪。通过后再估算其他两名主角、九套服饰、护具和八类敌人的成本；样板未通过不批量生产。
- 冷启动不加载整套动画；现有 `npm.cmd run check`、浏览器与真实 WebView2 对局通过。记录包体增量、解码内存、120 敌人场景 1% low 与长局趋势，不预先承诺具体 MB 或 FPS。

## 当前实施条件和停止规则

用户已提供 D 盘 Blender 便携版；本机核对为 Blender 5.2.2 LTS，后台 Python 与正交 Eevee 透明 PNG 导出均已成功。具体阶段、目录和游戏接口见 [巡线者实施计划](./ranger-dead-cells-animation-implementation-plan-2026-09-28.md)。工具已就绪；按原画修形、绘制材质和制作关键姿势的能力仍是主要质量风险。Blender 不会自动把 ImageGen 全身图变为合格动画。

下一步的第一个可验收成果应是**独立于游戏的灰模跑步与四向运动短片**，附源模型和镜头设置。玩家确认体积、视角与动作后，再上色、导出透明 2D 帧并接入游戏。若 3D 画风对齐失败，就暂停导出，改以同一动作标准试一名人物的专业 2D 手工关键帧；不要再次靠增加 IK 数值或随机补帧蒙混过关。
