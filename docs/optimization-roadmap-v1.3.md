# 《荒原回响》v1.3 优化执行路线图

状态：v1.3 计划已完成  
依据：`荒原回响_全面诊断与优化计划.md`（2026-09-12）与 v1.2 当前源码复核  
原则：先修正确性，再建立可测边界，然后优化性能与桌面交付；不以新增内容掩盖底层缺陷。

## 1. 对外部诊断的结论

整体判断合理，尤其是以下事实已经由当前源码确认：

- `GameModel`、内容注册表、世界注册表、输入、平台和渲染层之间已有清晰边界；
- 自动化基线为 112 项测试，另有 180 秒与 600 秒确定性模拟；
- 敌人此前只有世界边界夹紧，没有障碍碰撞和群体分离；
- 地图道路装饰仍含只适合旧城区的硬编码坐标；
- `canvas-renderer.js` 体积过大，继续直接堆叠页面和世界绘制会提高回归风险；
- `build:desktop` 目前只构建 Web bundle，不会产出可分发的 Windows 可执行文件；
- 素材发布目录约 31.2 MiB，以 PNG 为主，仍有安全瘦身空间。

报告并非所有优先级都应原样照搬：

1. **目录改名不属于 P0。** 工作区路径可能被外部工具和用户快捷方式引用，发布时通过产品名、包名与产物目录治理即可，源码根目录迁移应单独执行。
2. **Windows 外壳应先做技术决策再引入。** Tauri 2、WebView2 原生壳和其他方案会改变构建工具链；应先写 ADR、验证目标机 WebView2 与安装包需求，不能为了得到 `.exe` 破坏当前零运行时依赖的开发体验。
3. **渲染拆分不能以“每个文件小于 400 行”为目标。** 正确标准是依赖方向、可独立测试、稳定接口和视觉行为不变，行数只作为风险信号。
4. **离屏烘焙前必须先量化。** 需要记录 720p/1080p 的静态场景绘制次数、帧耗时和缓存内存，再决定整图缓存、分块缓存或仅缓存纹理层。
5. **成就和大量新内容不属于地基出口条件。** 它们应在碰撞、地图数据、渲染边界和桌面封装路线稳定后进入内容阶段。
6. **素材 12 MB 是方向性目标，不是质量红线。** 最终以视觉差异、解码内存和安装包体积共同验收，源 PNG 永久保留在 `art/`，只优化运行副本。

## 2. 执行顺序

### Step 0：冻结基线

- 输出：构建、112 项测试、180 秒与 600 秒模拟的当前结果；保留六页视觉截图基线。
- 验证：`npm.cmd run verify`，并记录 bundle、实体峰值、heap 与 RSS。
- 状态：已完成。初始基线 112 项测试通过；后续长局模拟继续在每个高风险步骤后执行。

### Step 1：战斗空间正确性

- 输出：敌人障碍碰撞、确定性群体分离、深度嵌入矩形的安全推出。
- 边界：不改变武器、伤害、刷怪曲线与地图数据。
- 验证：新增障碍出生、同点分离、重型敌人位移权重测试；再运行完整测试与双模拟。
- 状态：已完成。117 项测试通过；180 秒坚守获胜，600 秒无尽跑满并保持运行，3 波 Boss；bundle 为 391,694 bytes。障碍宽相改为静态空间索引后，600 秒压缩模拟由中间实现的约 25.5 秒降至约 2.5 秒，候选数组与去重集合均复用。

### Step 2：地图表现数据化

- 输出：把人行横道、路面裂缝等地图专属装饰移入 WorldRegistry 布局数据；三张地图不再共享错误坐标。
- 验证：世界注册表校验装饰边界；逐地图渲染测试；1280×720 与 1920×1080 截图。
- 状态：已完成。`roadDetails` 进入 WorldRegistry，可选扩展布局保持兼容；三张地图均有独立人行横道和裂缝坐标。118 项阶段测试通过，截图保存在 `output/playwright/v13-map-data/`，覆盖三图 1280×720 与 1920×1080。

### Step 3：渲染边界与性能基线

- 输出：先提取 `WorldView`、`HudView`、`MenuView`、`FxSystem` 的稳定接口，再决定静态层缓存方案；`CanvasRenderer` 保留协调职责。
- 验证：行为回归测试、六页截图 diff、战斗截图、帧耗时与缓存内存对比。
- 状态：已完成。特效、HUD、菜单路由与地表纹理分别拆入 `fx-system`、`hud-view`、`menu-view`、`world-view`；地表改为相机可视源裁切。1920×1080、81 敌人、600 帧基线约 0.655 ms/帧，堆增量约 0.96 MiB。

### Step 4：设置与桌面可用性

- 输出：音乐/音效连续音量、静音、UI 缩放预留；随后设计键位重绑与冲突检测。
- 验证：存档往返、键鼠与手柄菜单路径、720p/1080p 可读性。
- 状态：已完成。schema v7 保存 0–100% 音量、独立静音、80–120% UI 缩放和 13 项键位绑定；冲突自动交换，方向键/Enter/Tab 保留菜单导航。设置页双页签已完成 568p/720p/1080p 自动边界测试和真实浏览器截图。

### Step 5：运行素材管线

- 输出：WebP 运行副本、PNG 源图归档、显式 fallback、未启用素材不进入首屏加载。
- 验证：manifest SHA、像素级或感知差异阈值、冷启动与解码内存、缺图回退。
- 状态：已完成。10 个活动大型素材使用可复现 Pillow WebP 管线，24,643,363 bytes 降至 4,554,162 bytes（-81.52%）；透明 UI 无损，背景归一化 RMS ≤0.03。PNG 源、旧素材和生成归档未删除，`dist/` 仅复制活动运行素材。

### Step 6：Windows 封装决策与最小原型

- 输出：一份 ADR 比较 Tauri 2 与直接 WebView2 外壳；选定后只做启动、存档、窗口、全屏、图标与崩溃日志的最小原型。
- 验证：干净 Windows 10/11 环境双击启动、30 秒战斗、暂停、退出和存档回读。
- 状态：已完成。ADR-001 选择 Tauri 2 + WebView2；`dist/` 为 5,010,164 bytes，窗口、图标、CSP、localStorage 和崩溃日志已配置。Visual C++ Build Tools 与 Windows SDK 已安装，现归档于 `archive/releases/v1.3.0/WastelandEcho-v1.3.0-win-x64.exe` 的便携版成功生成（13,139,968 bytes）；启动窗口标题正确、工作集约 28.6 MiB，标准关闭成功且无崩溃日志。

### Step 7：首轮玩法纵切

- 输出：敌人签名动作、Boss 阶段、升级进化、地图互动和 Meta 进程，按独立内容包接入。
- 验证：ContentRegistry 契约、确定性模拟、平衡记录和真人试玩。
- 状态：已完成首个系统化纵切，但不等同于长期玩法深化完成。新增 4 条带前置条件且优先出现的终局进化；Boss 三阶段弹幕/召唤/追踪重炮与常驻阶段血条；坦克冲锋与警报者尖啸；三图爆炸桶、补给箱、电磁减速区；8 项一次性成就奖励。135 项测试及 180/600 秒模拟通过；机制化构筑、规则解锁和熟练度奖励留待后续路线。

## 3. 每步统一完成门槛

1. 新逻辑有失败前可复现、修复后可通过的自动测试；
2. 不手改 `web/game.bundle.js`，统一由构建脚本生成；
3. UI 或渲染变化必须做真实浏览器截图验收，HTTP 200 只算启动检查；
4. 高风险规则或性能变化执行 `npm.cmd run verify`；
5. 停用素材只归档，不删除；新旧资源同步更新素材清单；
6. 文档、组件目录和测试矩阵随里程碑更新，避免规格再次落后于实现。
