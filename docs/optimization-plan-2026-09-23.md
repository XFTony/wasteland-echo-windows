# 《荒原回响》Windows 版全面复审与执行计划

复审日期：2026-09-23。当前开发版本：`1.5.0-alpha.1`；公开稳定基线：`v1.4.0`。本计划基于当前源码、测试、文档、发布物和既有真实页面截图；历史版本记录只作对照。优先级 P0 = 数据或发布阻断，P1 = 核心体验，P2 = 内容深度，P3 = 扩展方向。工时为单人有效开发日的粗估，首次执行后更新。

## 一、现状和证据

| 维度 | 当前状态 | 复审判断 |
|---|---|---|
| 玩法 | 3 章/地图、3 模式、3 英雄、7 枪、8 类敌人，含 Boss、机制卡、进化、15 条解锁规则 | 已有可玩纵切，当前更需要真人反馈与系统收敛 |
| 工程 | Canvas 2D、CommonJS、本地资源、Tauri 2/WebView2；core/input/render/platform 分层 | 边界总体清晰；`GameModel` 仍承担较多会话和存档职责，按实际耦合拆分 |
| 自动验证 | 2026-09-23 本机 `npm.cmd test` 为 191/191 通过；既有六策略矩阵为 3/6 通过 | 回归较强，但模拟代理不能证明手感、读图和玩家胜率 |
| 性能 | 既有系统 Edge headless 18 场景，最低 1% low 72.46 FPS；资源包约 5 MB | 数据只代表该机器与该浏览器；WebView2 窗口和低配机仍待测 |
| 视觉 | 六张全页场景图、活动 WebP 与人物像素组合均已实现 | 1080p 背包快照中说明字偏小，深背景与暗槽位影响扫读；战斗与菜单风格落差可进一步收敛 |
| 存档 | schema 9、旧档迁移、LocalStorage；启动即调用 `persist()` | 主存档解析失败后会用新档覆盖原字符串；写入失败无用户提示，需先修 |
| 发布 | 稳定版在 `release/`，alpha 在 `output/builds/`；NSIS 安装和卸载 smoke 已有记录 | 缺真人完整流程、低配/Win10、签名和商业资产复核；不应宣布 alpha 就绪 |
| 目录 | 源码约 0.5 MB，`src-tauri/target` 约 1.4 GB，`art` 约 80 MB | target 是可再生构建缓存；源图、许可证、旧版本发布物和截图是证据，不做无依据清理 |
| 版本管理 | 当前目录不是 Git 仓库 | 下一批开发前需要建立可回退的版本基线与忽略规则；二进制素材和发布包应明确存放策略 |

## 二、排序原则与交付门槛

1. 先保护玩家数据、确认真实可玩性，再调规则和添加内容。任何影响存档、输入、经济、地图的改动，先留可复现案例，再做最小改动。
2. 每一批保持可独立验收；源码改动不直接覆盖稳定 `release/`，生成文件由构建脚本刷新。
3. 基线分三类：自动测试/模拟、浏览器或桌面真实运行、真人感受；三类结论分别标注。
4. 不以单 seed、单策略代理决定难度；每次平衡至少观察 3 个 seed × 6 种策略，再结合真人记录。
5. P0/P1 完成并且发布门槛通过之前，P2 内容扩展只做原型，不向正式包堆数量。

## 六、每批复验与风险控制

- 规则/存档/输入：`npm.cmd run build`、`npm.cmd test`、正常生命六策略矩阵、600 秒无尽模拟；涉及性能再跑系统 Edge 页面采样和桌面长局。
- UI/音频：保存同分辨率前后截图或短录屏；至少测 720p、1080p、1440p 和 125% Windows 缩放，实体手柄焦点路径另验。
- 发布：保留 `release/` 的 v1.4.0；alpha 继续进入独立 `output/builds/`；逐一核对版本、文件 SHA、安装/卸载、存档未丢与签名状态。
- 任何单机自动试玩、headless 采样、静态截图都不写成真人验收。需要玩家才能判定的条目在表中保持待人工。
