## 4. 必须优先处理的发现

### F01 · 发布包混合了不同构建（P0）

`output/builds/v1.5.0-alpha.1/` 的独立 exe 为 18,560,000 bytes，9 月 28 日更新；zip、setup 与校验文件仍是 9 月 23 日。zip 内 exe 为 13,212,160 bytes，哈希与旧构建记录一致，而外部 exe 哈希不同。两者的版本标识都叫 1.5.0-alpha.1，无法由文件名判断实际内容。

`build-desktop.ps1` 只覆盖独立 exe，`build-installer.ps1` 才会一起生成 setup、zip 与 SHA。这能解释当前文件组为何不一致；不能由此断言新 exe 对应当前源码。**建议保留现有历史文件和清单，另建有源码 SHA 的内部构建目录；下一次真正的公开候选统一递增版本并全套重建。**不要只重算 SHA，也不要把旧 zip 当作当前插画版。

### F02 · 最新开发缺少远程备份（P0）

本轮审核的游戏源码 HEAD=`c941eec`，比 main 多 28 次提交；`feat/illustrated-overhaul` 和 `codex/ranger-3d-motion-pilot` 都没有 upstream，远端只存在 main。建议先原样推送这两个开发分支并确认远端 SHA，保留 main 的质量与合并边界；备份动作不要求把未完成灰模合并 main。关键截图、录屏和构建包在 Git 忽略目录，仍需单独备份。

### F03 · 动画生产流程还没有闭环（P0，当前主要功能目标）

游戏的 `illustrated-actors.js` 仍画整张身体，以输入方向是否非零决定上下浮动，只按瞄准 X 镜像。没有新图集、真实位移驱动步相、四向/背向动作或导出的握点。撞墙持续按移动键时仍可被视为“正在移动”。Blender 样板过关只代表源能继续制作，不代表玩家游戏里的人物已经活起来。

先完成巡线者默认服饰＋起始手枪。特别是后向瞄准：当前 4 角度检查只在**第 1 帧**测可达性，枪械背向仍被身体遮挡；不能称作全方向移动瞄准已验收。现有循环接缝检查主要比较位置，V3 新增的根旋转、脚掌角度、极点和衣摆旋转也应纳入检查。人体交叉、衣摆穿腿和枪口可见性需要逐姿势目视判断。

### F04 · “物品图齐全”不等于“穿戴外观齐全”（P1）

当前插画人物绘制成功后直接返回，护具数据仅在旧像素回退路径参与人物外观。属性正常生效，但背包/战斗中的插画身体没有对应四槽换装。继续用产品图拉伸覆盖会重现前期失败；应在同一角色源上做头、胸、腿、靴的可替换部件，先验一件胸甲再扩展。

### F05 · 两图对象与剩余符号未统一（P1）

新地表和角色已带来一致的色彩，但锈轨和赤砂的建筑、围栏、车厢仍明显是平面代码物件；重复高对比轨枕/围栏容易抢占视线。第一图也有广播塔、围栏、目标标识等未统一。优先做可复用物件，保持碰撞数据为唯一放置依据；26 个升级符号用统一原生绘图语言即可，不必每件生成一张大图。

### F06 · 尚有可确认的活动资源浪费（P1，低风险）

`ui.field-plate.v2` 和 `deployment.convoy.v1` 仍为 active，合计 **1,809,706 bytes**，stage 会复制两者。当前 `field-surfaces.js` 已改为代码绘制，部署页也不再请求车组图；搜索活动源码未见两 ID 的实际绘制使用。旧 field plate 还标为 eager，会在初始化请求其图片。

建议在后续独立小提交中停用这些定义、核对 manifest 与缺图回退，再检查菜单截图与 staging。保留源归档，不删除唯一素材。旧 plate 的 RGBA 像素约 3.0 MiB；车组未 eager，不应把它也算作必然启动解码。此次审核不修改活动素材。

### F07 · 自动门槛与文档目标不一致（P1）

性能脚本 `--assert` 只检查 1% low ≥30 FPS，规格/计划目标是 50 FPS。本次快速样本 47.96 仍返回成功，完整 18 场景最终均达到 50，因此不能据此定为持续性能故障，但必须分清“最低下限”和“常规目标”。建议门槛参数化并分别输出，不把某次 headless 平均 170–240 FPS 当作真实 WebView2 可保证的 FPS。

目前 54 个 active 图片压缩合计 9,832,928 bytes（约 9.38 MiB）；如果全部同时解码，理论 RGBA 像素约 94.67 MiB。这是全部图片的合计估算，**不是当前进程已用内存**。现有按场景释放有价值；后续动作图集必须另外量解码峰值，例如 2048×2048 RGBA 图集本身就是 16 MiB。

### F08 · 发布体验证据不足（P1，公开发行阻断项）

真人七局表仍全部待填；缺实体手柄有线/蓝牙、热插拔、真实 WebView2 至少 8 分钟、Windows DPI、低配机和新候选安装/卸载/重启存档的记录。当前不得把这些列为通过。可以先对当前静态版做基线试玩，最终动画版再重复相关项，避免美术完成后才发现输入或窗口问题。

### F09 · 文档和统计已有明显漂移（P1）

README、CREDITS、旧材料审计及测试矩阵仍写像素分层角色、10 个活动图片、171/191 项测试或旧 bundle 大小；当前分别是静态插画路径、54 图片、208 项测试、77 模块。截图脚本声称 94，实际输出 104。历史记录应保留原日期；现行 README 和总计划应链接本报告并明确有效日期。以“当前源码＋证据摘要”维护状态，避免不断新增互相矛盾的完成率表。

## 7. 当前体验入口

最新活动静态游戏可从仓库根运行 `npm.cmd run play` 后打开终端地址，通常为 `http://127.0.0.1:4173/`。这会使用当前源码和插画，不受混合的历史 alpha 安装文件影响。

巡线者新动作仍是内部预览：空手在 `output/animation/ranger/color-study/unarmed/review.html`，持枪在 `output/animation/ranger/color-study/sidearm/review.html`。两者的简单色块不是最终厚涂美术。正式游戏中的英雄和敌人现在依然使用整张静态身体图。
